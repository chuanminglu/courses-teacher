① Core Knowledge
核心知识体系与最佳实践
软件设计知识体系（IEEE 1990）：6大领域 — 基本概念 / 关键问题（并发·分布·持久）/ 结构体系 / 质量评价 / 表示法 / 策略方法
设计完整流程：需求 → 架构设计（SAD + 架构评审）→ 概要设计（HLD + 评审）→ 详细设计（评审）→ 进入开发
OOAD 与 UML 建模：用例图（需求捕获）· 类图（静态结构）· 序列图（动态交互）· 状态图（行为）· 活动图（流程）
面向对象设计原则（SOLID）：重点展开 OCP 开闭原则 — 对扩展开放 / 对修改封闭，案例：支付策略模式
架构设计工具：C4模型 / ADR架构决策记录 / DDD限界上下文 / STRIDE威胁建模 / 质量属性场景（ASR）

③ Practice Flow · 本章重点章节
演练流程： ADR → SAD → HLD → 详细设计
1
ADR（架构决策记录）：给定技术选型问题，AI生成背景 / 备选方案 / 决策 / 影响，含量化对比矩阵
2
SAD（系统架构设计）：C4模型驱动，AI生成 Context / Container / Component 架构图（PlantUML）
3
HLD（概要设计）：模块划分 + 接口契约（OpenAPI）+ ER图，AI辅助输出HLD文档结构
4
详细设计：类图 + 序列图 + 异常处理设计，AI生成UML及代码骨架，并做OWASP安全检查

⑤ Anti-Patterns
反模式警示
❌ AI生成的架构/领域模型
直接采用，跳过评审
门禁流程
❌ SAD/HLD文档形式堆砌，
与代码实现严重脱节
❌ 重功能轻质量：忽视
性能 / 安全 / 可观测性
等非功能需求（NFR）
✅ 设计阶段AI价值在于
"提速 + 检查"，关键
架构决策需人工确认
KEY INSIGHT
好的设计是代码的宪法；
AI加速文档输出，
架构判断不可外包
