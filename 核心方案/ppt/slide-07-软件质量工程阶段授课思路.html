① Core Knowledge
核心知识体系与最佳实践
通用软件质量工程体系：ISO 25010八大质量特性（功能性/性能/兼容/可用/可靠/安全/维护/可移植）；质量体系双轮驱动：质量策略（做什么·测试分层金字塔/左移右移时机）+质量实践（怎么做·Code Review/自动化/门禁）
灯塔模型·质量体系5大要素：五层结构：质量愿景(Vision)→质量策略(Strategy)→质量实践(Practices)→质量人员(People)→基础设施(Infrastructure)；人与工具缺一不可，灯塔之光=业务价值达成
质量门禁（Quality Gate）：代码质量门（SonarQube评分≥A）/ 单元测试覆盖率门（分支覆盖≥80%）/ 安全漏洞门（零Critical/High）/ 性能基线门（P95响应时间＜SLA）；质量门禁=CI/CD第三方节点
AI质量工程全景架构（四层）：战略层(ROI预测·KPI·竞品对标)→管控层(质量计划·风险雷达·根因引擎)→实践层(Dev需求/代码·Test用例/发布门禁)→基础层(AI测试平台·智能CI/CD·私有模型·工具链)
Playwright E2E自动化核心：基于Chromium/Firefox/WebKit；Page Object Model（POM）封装；AI生成Locator+断言；并发测试+Trace Viewer+HTML Report；与CI/CD门禁集成

③ Practice Flow Playwright E2E → AI用例生成 → 质量门禁配置 → 代码质量审查
1
Playwright构建自动化E2E测试：项目初始化 → Page Object Model（POM）封装页面元素 → AI辅助生成Locator+断言 → 并发执行（3浏览器×N用例）→ HTML Report+Trace Viewer接入CI
2
AI驱动测试用例生成（721模型）：DeepSeek/Copilot基于需求文档生成Happy Path(70%) + 边界Edge Case(20%) + 异常Error Case(10%)；人工评审+去重+录入测试管理平台
3
质量门禁实战配置：SonarQube规则集定制（代码异味/圈复杂度/重复率）→ GitHub Actions质量门步骤→ 覆盖率报告(JaCoCo/Istanbul) → 门禁不通过则阻断PR合并
4
AI辅助代码质量审查：技术债务AI量化识别（SQALE模型）→ Copilot Review自动点评高风险代码 → 安全漏洞扫描（OWASP Top10映射）→ 改进建议闭环追踪

⑤ Anti-Patterns
反模式警示
🔭 灯塔理念：
质量不是测试出来的，
而是设计与构建进去的
❌ 测试覆盖率造假：
只写没有断言的测试凑
覆盖率数字，毫无保障
❌ AI用例不复审：
AI生成后直接入库，
错误用例掩盖真实缺陷
⚠️ 质量门禁形同虚设：
设了门禁但允许"例外"
跳过，最终零拦截作用
⚠️ 只靠E2E兜底：
缺单元/集成测试塔底，
E2E慢且定位缺陷困难
KEY INSIGHT
AI提升测试效率，
人决定质量标准；
门禁不是障碍，
是质量的护城河
