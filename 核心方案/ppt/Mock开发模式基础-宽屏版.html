MOCK 基础 前后端分离开发核心技术
什么是 Mock 开发
💡 核心概念
🎯 核心定义
Mock 开发是指在前后端分离开发模式下，前端开发者基于接口契约创建模拟数据（Mock Data），搭建本地 Mock 服务器，无需等待后端接口完成即可进行 UI 开发、交互逻辑实现和功能测试的开发方式。
📋
FEATURES
Mock 开发的核心特征
  • 契约驱动：基于前后端共同定义的接口文档（Swagger/Apifox）
  • 数据模拟：前端创建符合契约规范的假数据（JSON）
  • 本地服务：搭建本地 Mock 服务器拦截 API 请求
  • 独立开发：前端不依赖后端进度，并行开发
  • 无缝切换：后端完成后只需切换 API 地址
  • 快速验证：可提前测试 UI 交互和错误处理
💡 关键理解：Mock 不是"假功能"，而是用模拟数据替代真实后端，让前端开发流程完整运转。
🔄
WORKFLOW
Mock 开发工作流程
  • Step 1：定义契约 → 前后端共同评审 API 接口文档
  • Step 2：创建 Mock → 前端根据契约编写 Mock 数据
  • Step 3：搭建服务 → 配置 Mock 服务器（json-server/MSW）
  • Step 4：前端开发 → 调用 Mock 接口开发 UI
  • Step 5：后端开发 → 后端并行实现真实接口
  • Step 6：联调验证 → 切换真实接口，验证数据一致性
⚡ 效率提升：传统串行开发需要 20 天，Mock 并行开发可缩短至 12-15 天，效率提升 30-40%。

PROBLEMS
传统串行开发的痛点
  • 前端等待后端：接口未完成前，前端无法开始开发
  • 开发周期长：前后端串行开发，工期翻倍
  • 联调成本高：接口调试问题只能在后期集中爆发
  • 测试不充分：前端无法提前测试异常场景
  • 资源浪费：前端开发者在等待期闲置
  • 风险集中：问题在联调阶段集中暴露，影响交付
📊 数据：传统模式下，前端等待时间占项目周期的 25-35%，严重影响交付效率。
✅
BENEFITS
Mock 开发的核心优势
  • 并行开发：前后端同时开工，开发周期缩短 30-40%
  • 快速验证：前端可提前验证 UI 交互和边界场景
  • 降低风险：问题在开发阶段分散发现和解决
  • 提升质量：前端可充分测试错误处理逻辑
  • 资源优化：前端开发者持续产出，无等待时间
  • 团队协作：接口契约成为协作基础，减少沟通成本
🚀 实践效果：采用 Mock 开发的团队，交付速度平均提升 35%，联调问题减少 50%。

SOLUTIONS
主流 Mock 技术方案
🚀 MSW (Mock Service Worker)
通过 Service Worker 拦截网络请求，最接近真实场景
  • 无需修改业务代码
  • 支持浏览器和 Node.js
  • 可模拟网络延迟
  • TypeScript 友好
⚡ json-server
快速搭建 RESTful API Mock 服务器，零配置
  • 30 秒启动 Mock 服务
  • 支持 CRUD 操作
  • 支持路由和中间件
  • 适合快速原型开发
🎲 Mock.js
前端 Mock 数据生成器，语法简洁
  • 随机数据生成
  • 拦截 Ajax 请求
  • 中文文档友好
  • 学习成本低
☁️ Apifox / Postman Mock
在线 Mock 平台，团队协作能力强
  • 云端 Mock 服务
  • 可视化配置
  • 团队共享接口
  • 自动生成文档
