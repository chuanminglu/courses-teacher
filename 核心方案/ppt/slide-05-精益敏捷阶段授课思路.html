① Core Knowledge
核心知识体系与最佳实践
传统 vs 精益 vs 敏捷三角对比：瀑布（计划驱动·需求冻结·晚期交付）→ 精益（消除浪费·价值流·快速流动）→ 敏捷（迭代·响应变化·持续交付）
精益软件开发7大原则（Poppendieck）：消除浪费 / 放大学习 / 尽晚决策 / 尽快交付 / 授权团队 / 内建质量 / 全局优化；软件开发7大浪费识别
敏捷宣言与12原则精要：4价值观（个体>流程·软件>文档·合作>合同·响应>计划）+ 敏捷方法家族：Scrum / Kanban / XP / SAFe
Scrum框架精讲（3-5-3-3）：3角色（PO/SM/Dev）· 3支柱（透明/检视/适应）· 5事件（Sprint+4会议）· 3工件（PBL/SBL/Increment）
用户故事与估算实践：INVEST原则 / Given-When-Then验收条件 / 故事点+计划扑克估算 / DoD（完成定义）制定
④ 翻转课堂 · 学员讲解与检验
演练完成后，每组学员自行上台讲解：
› PBL是否具备INVEST特征，优先级是否合理？
› Sprint目标是否聚焦且可验收（DoD清晰）？
› AI编程计划能否直接驱动Copilot落地执行？

③ Practice Flow PBL梳理 → Sprint规划 → 任务拆解 → AI编程计划
1
Product Backlog管理与梳理：AI辅助Epic→Feature→Story三层拆解；MoSCoW法+WSJF算法智能优先级排序；INVEST原则合规检查
2
Sprint迭代规划：AI生成Sprint目标（清晰·可验收）；智能团队容量计算；DoD验收标准自动生成；Sprint Backlog构建
3
任务拆解与估算：Story→Task拆解（≤8h颗粒度）；AI辅助计划扑克故事点估算；依赖关系识别；燃尽图基线自动生成
4
AI编程执行计划：SDD+TDD上下文管理（Context Engineering）；Copilot任务提示词设计；代码-测试-文档一键生成流水线

⑤ Anti-Patterns
反模式警示
❌ 形式化敏捷：
站会变成汇报会
Sprint = 小瀑布式计划
❌ AI生成PBL未验证：
跳过PO审核直接进Sprint
导致方向偏差与返工
❌ 精益走形式：
七大浪费只贴标签
没有根因分析与改进闭环
✅ AI是敏捷加速器，
不是替代团队思考
与协作的工具

精益消浪费，敏捷响变化；
AI放大团队智慧，
人决定方向与价值
