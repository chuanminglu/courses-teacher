# 课前测评 · 讲师参考答案与能力画像评分标准

> 仅供讲师/项目组内部使用，请勿分发给学员。

## 使用方式

1. 课前1~2天收集学员测试卷（纸质或问卷形式均可），按本文档评分。
2. 单选题按"知识维度"归类统计对错，快速定位班级整体的薄弱模块，据此决定课上哪些环节需要加重讲解、哪些可以一带而过。
3. 第15题（自评频率）与主观题16/17不计对错，用于给学员分层（建议按"高频实践组"和"初学摸索组"混合分组，形成传帮带），并提前掌握团队在安全合规认知上的真实盲区，针对性设计课上的"AI失效场景"讨论案例。
4. 建议同时统计"opencode / GitHub Copilot"实际使用比例，课上工具演示环节可据此调整两个工具的演示配比。

## 能力画像与班级整体诊断参考

### 单选题正确率分层建议

- **≥80%（12题以上正确）**：具备较扎实的AI基础认知，课上可适当加快模块一、模块二的理论讲解节奏，把更多时间留给动手实践与跨章综合演练。
- **50%~79%**：认知参差不齐，建议保留完整的"①核心知识体系→②AI赋能全景→③演练要点"结构，尤其加强安全合规（第5/6题）与"AI是辅助非替代"（第4/8/9/10/13题）相关内容的讲解深度。
- **<50%**：团队对AI辅助研发整体较陌生，建议第1天适当延长模块一、模块二的时间，增加更基础的工具操作演示（GitHub Copilot / opencode 基本用法），并在每章"演练"环节降低任务难度、提供更完整的模板。

### 安全合规专项诊断（第5、6题 + 主观题17）

由于友邦咨询属金融行业、对安全要求高，这两题及主观题17的作答质量应作为**课程内容调整的核心依据**：

- 若第5/6题错误率较高，或主观题17回答空泛（答不出具体注意事项），建议在模块一"AI技术选型策略"及模块七"AI辅助编码核心应用场景"中，专门增加10~15分钟的"金融行业AI工具使用红线"专题讨论（可参照课程设计中"AI失效场景"专项讨论的建议，结合客户真实的数据分类分级要求定制案例）。
- 若普遍答得较好，说明团队已有基本的安全意识，课上可将该话题作为"深化"而非"启蒙"来处理，重点转向如何在合规前提下提升效率（如私有化部署工具的最佳实践、脱敏技巧等）。

### 工具使用现状诊断（第15题 + 学员填写的"当前主要使用工具"）

- 统计 opencode / GitHub Copilot 的实际使用比例与熟练度分布，用于决定模块二"六层DevOps AI工具集"演示环节中两个工具的演示时长配比，以及模块七"AI辅助编码核心应用场景"动手实践环节的工具选择。
- 若团队中"偶尔用过/基本没用过"（C/D选项）比例较高，建议第1天课前准备阶段增加更基础的工具环境搭建与首次上手指导，避免后续动手实践环节因工具不熟悉而拖慢进度。

### 主观题16诊断要点

重点关注学员描述中是否体现：
1. 是否有**具体、真实**的工作场景（而非泛泛而谈"用过Copilot写代码"）；
2. 提示词设计是否已具备基本的结构化意识（角色/背景/约束/格式）；
3. 对AI输出是否有**主动修改/校验**的习惯，还是"生成即用"。

若多数学员反馈"生成即用、很少修改"，应在模块七"反模式警示"环节重点强化"AI是高级实习生，代码所有权在开发者"的认知，并在动手实践评分维度中加重"人工修正点说明"的权重。
