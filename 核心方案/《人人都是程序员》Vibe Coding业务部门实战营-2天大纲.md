### 课程背景：一个正在改变世界的时刻

2025年，特斯拉前AI总监 Andrej Karpathy 在推特上发了一条让全球程序员震惊的帖子：

> *"There's a new kind of coding I call 'vibe coding', where you fully give in to the vibes, embrace exponentials, and forget that the code even exists."*
> ——Andrej Karpathy

**他的意思是**：你不需要写代码，你只需要描述你想要什么，AI 帮你实现它。

这不是程序员的专利。斯坦福大学在 2025 年的《The Modern Software Developer》课程中指出：**未来最有竞争力的不是会写代码的人，而是最懂业务、最会表达需求的人**——因为 AI 已经接管了"翻译成代码"这一步。

**这意味着什么？**

- 销售总监可以亲手做一个实时跟进客户的看板；
- HR 经理可以在一个下午搭出一套入职自动化工作流；
- 财务主管可以让 AI 把散乱的 Excel 变成会自动计算、会预警的智能报表；
- 运营专员可以把脑子里的"如果……就……"业务规则，变成真正运行的自动化程序。

**本课程就是让这件事在两天内真实发生。**

### 课程核心理念

```
传统逻辑：想法 → 写需求文档 → 等IT排期 → 开会确认 → 等开发 → 测试 → 上线（3个月）

Vibe Coding：想法 → 跟AI对话 → 看到原型 → 调整 → 上线使用（3小时）
```

本课程不教你如何"学编程"，而是教你如何**用母语驾驭 AI**，把脑子里的业务想法变成真正能用的数字化工具。

#### 模块二：提示词——你的新型编程语言

> 🎯 目标：掌握"说清楚需求"的核心技能

**这是整个课程最重要的模块。**

**2.1 为什么你说的 AI 听不懂？**

**【现场对比实验】**

同一个需求，两种说法：

❌ 糟糕的提示词：

```
帮我做一个销售报表
```

✅ 好的提示词：

```
我是一家电信公司的销售经理。
我需要一个月度销售追踪工具，要求：
1. 可以输入每个销售人员的名字和当月业绩数字
2. 自动计算达成率（目标是每人10万）
3. 用颜色区分：绿色=达标，红色=未达标，黄色=接近达标（90%以上）
4. 最后显示整个团队的总业绩和平均达成率
输出为一个可以在浏览器直接打开的 HTML 文件，不需要安装任何软件
```

**现场演示**：两种提示词的输出差距

**2.2 业务人员的提示词黄金公式（SCQA框架）**

```
S（Situation 背景）：我是谁？在什么场景下？
C（Complication 问题）：遇到什么麻烦/需求？
Q（Question 目标）：我想实现什么？
A（Answer 约束）：需要满足哪些条件/限制？
```

**2.3 让 AI 越来越懂你的技巧**

- **具体化**：不说"漂亮"，说"用蓝白配色，表格有斑马纹，字体大一点"
- **举例子**：上传一张你想要的效果图，让 AI 模仿
- **分步走**：大需求切碎，一步一步来
- **纠偏法**：AI 做错了怎么说？"不对，我要的不是……，而是……"
- **三闸口验证**：如何避免 AI 一本正经地胡说八道？

#### 模块七：安全与边界——Vibe Coding 的正确姿势

> 🎯 目标：知道能做什么、不能做什么、要注意什么

**这个模块同样重要——会用，也要用得安全。**

**7.1 【真实案例】某公司数据泄露事件**

> 2024 年，某公司员工把含有客户隐私的 Excel 直接上传 ChatGPT 处理，导致数据被用于模型训练。
>
> **血泪教训：公司数据、客户信息，一定要脱敏后再给 AI 处理。**

**7.2 业务人员必须知道的 AI 安全红线**

- 🔴 **绝对不传**：身份证号、银行卡号、密码、未公开合同、客户个人信息
- 🟡 **脱敏再传**：销售数据（去掉客户名）、员工绩效（去掉真实姓名）
- 🟢 **可以直接用**：公开资料、已脱敏数据、自己写的需求描述

**7.3 识别 AI 在撒谎：三闸口验证法**

AI 会一本正经地给出错误答案。业务人员的验证三问：

1. **逻辑问**：这个结果符合业务常识吗？
2. **来源问**：这个数字/结论，AI 是从哪里得出的？
3. **测试问**：用一个你知道答案的数据，测试工具是否算对了？

**7.4 Vibe Coding 的能力边界**

| 适合 Vibe Coding 的  | 不适合 Vibe Coding 的       |
| -------------------- | --------------------------- |
| 内部小工具、原型验证 | 核心业务系统（需要专业 IT） |
| 数据处理和可视化     | 涉及金融交易、资金安全      |
| 自动化日常重复工作   | 需要高并发、高稳定性的系统  |
| 快速验证业务想法     | 需要与现有系统深度集成      |
