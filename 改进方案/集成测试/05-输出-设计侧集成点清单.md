## 第1部分：集成点清单表

| IP编号 | 链路描述（组件A → 组件B） | 类型（调用/事件/数据/外部依赖） | 风险等级（高/中/低） | 判断依据 | 证据标签 |
|---|---|---|---|---|---|
| IP-1 | `TaskService.complete → ApplicationEventPublisher.publishEvent → NotificationService.onTaskCompleted`（`@EventListener`） | 事件 | 高 | 异步接缝，发布与订阅是两个独立组件，一旦漏发/未订阅成功不会有编译期提示，只能靠集成测试捕获（来自 02 §四、03 §二代码取证） | [FACT] |
| IP-2 | `TaskService → TaskRepository`（`save`/`findById`/`deleteById`/`findAll`） | 调用+数据 | 中 | 业务逻辑与持久化层的读写契约，接口变更或实现类行为不一致会导致数据不一致（来自 02 §四、03 §一类依赖表） | [FACT] |
| IP-3 | `create → assign → complete` 跨方法编排 | 调用链 | 中 | 同一实体在多个 Service 方法间连续流转状态，需验证多步操作组合后的最终状态是否正确（来自 03 §五） | [FACT] |
| IP-4 | `delete → canDelete → Task.isCompleted()` | **规则跨方法** | **高★** | 业务规则跨越 delete 与 canDelete 两个方法；03 §三代码取证显示 `delete` 当前**未调用** `canDelete` 校验（已知缺陷），是本次抽取的核心风险点 | [FACT] |
| IP-5 | `findOrThrow → BusinessException → @ExceptionHandler` | 异常 | 中 | 跨 Service 抛异常与 Controller 异常映射两层，直接决定 API 对外契约（403/404）（来自 02 §四、03 §四） | [FACT] |
| IP-6 | 外部依赖（真实数据库/第三方服务） | 外部依赖 | 不适用 | 本项目当前使用 `InMemoryTaskRepository` 内存实现，无真实外部依赖；若未来接入真实 DB 需补充 Testcontainers 类集成点（来自 02 §四、03 §五） | [FACT] |

## 第2部分：高风险接缝清单

## 第3部分：设计与代码的差异说明

- 02 设计文档的接缝清单中，`Controller → Service`（5 个 REST 入口全部走 Service）被列为一条独立的"方法调用"接缝；但 03 代码依赖清单的最终 IP-1~IP-6 编号中**未单独为其编号**，而是分散体现在 IP-2（Repository 读写）、IP-3（编排链路）、IP-4（删除规则）、IP-5（异常链路）等更具体的业务动作链路中。判断：这不是设计与代码的实质冲突，而是**粒度差异**——02 是宏观视角的接缝分类，03 按具体业务动作做了进一步细化。`[INFER]`
- 02 的接缝清单未单独列出"create → assign → complete 跨方法编排"，该项由 03 §五补充为 IP-3。判断：属于代码依赖清单对设计文档的**细化补充**，非遗漏冲突。`[INFER]`
- 其余接缝（事件、规则跨方法、异常映射、外部依赖）在 02 与 03 中描述一致，无差异。`[FACT]`

## 第4部分：反模式自检

对照 `prompts/02-设计代码侧集成点抽取.md` 中列出的 6 条已知反模式，逐条自检：

1. **只画"正常调用链"，漏掉异常传播路径**：IP-5 异常链路已作为独立集成点列出。**未触犯**。
2. **把同模块内的类间调用误判为集成点**：清单中的 6 个 IP 均为跨组件/跨层交互（Controller/Service/Repository/NotificationService 之间），未纳入模块内部实现细节。**未触犯**。
3. **漏掉异步/事件驱动的隐式依赖**：IP-1 事件接缝已被识别并标为高风险。**未触犯**。
4. **漏掉外部依赖类接缝**：IP-6 已显式检查，并说明当前无真实外部依赖（内存仓储），而非直接省略不提。**未触犯**。
5. **只看代码依赖不看设计意图（或反之）**：本次同时依据 02（设计意图）与 03（代码实证）两份材料，并在第3部分显式列出两者的粒度差异。**未触犯**。
6. **风险等级评估主观化**：每条 IP 的风险等级均给出具体理由（如"IP-4：已知缺陷 + 跨方法规则 → 高"，而非笼统标"中风险"了事）。**未触犯**。
