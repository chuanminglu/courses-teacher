## 二、事件链路（代码级取证）

**发布端** —— `TaskService.complete`：
```java
task.setStatus(TaskStatus.COMPLETED);
task.setCompletedAt(LocalDateTime.now());
taskRepository.save(task);
eventPublisher.publishEvent(new TaskCompletedEvent(task));   // ← 集成点：事件发布
```

**订阅端** —— `NotificationService.onTaskCompleted`：
```java
@EventListener
public void onTaskCompleted(TaskCompletedEvent event) {
    notifications.add(event);                                 // ← 集成点：事件接收
}
```

**计数/清理**（集成测试断言用）：
```java
public long totalNotifications() { return notifications.size(); }
public void clear() { notifications.clear(); }
```

## 三、规则链路（代码级取证）★ 本案例被漏的接缝

```java
// delete —— 缺陷版：没有调用 canDelete，直接删
public void delete(Long id) {
    Task task = findOrThrow(id);
    // BUG（故意保留）：缺失 canDelete(task) 校验
    taskRepository.deleteById(id);
}

// canDelete —— 规则载体（TODO 处缺失"已完成不可删"判断）
public boolean canDelete(Task task) {
    if (task == null) { return false; }
    // TODO 讲师演示：在此补上 if (task.isCompleted()) return false;
    return true;
}
```

> **代码依赖清单的价值**：一眼看清"删除规则"是 `delete → canDelete → Task.isCompleted()` 的**跨方法链路**——它完全符合集成测试的对象，只是当初用例清单里没有它。

## 四、异常链路（代码级取证）

```java
private Task findOrThrow(Long id) {
    return taskRepository.findById(id)
            .orElseThrow(() -> BusinessException.notFound("任务不存在: id=" + id));
}
// Controller：@ExceptionHandler(BusinessException.class) → 返回 body.status
```
