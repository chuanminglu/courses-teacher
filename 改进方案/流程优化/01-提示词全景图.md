## 1.3 关键观察

1. **B4-07 是唯一被 HLD-01/02/03 三份文档同时标注"强制前置"的材料**，它把跨故事的隐性关系（共享聚合、状态机、事件链、数据依赖、横切关注点、并发冲突）显式化，是 HLD 阶段设计质量的地基。
2. **HLD-01 是唯一的"承上启下"枢纽**：它消费 SAD（技术栈/架构风格），产出模块清单给 HLD-02 和 HLD-03 同时使用。HLD-02 和 HLD-03 彼此并列、互不依赖，理论上可以并行生成。
3. **HLD-02/03 → Sprint任务拆解 这一棒，是全链路里唯一"文档粒度不匹配"的一棒**：HLD-02/03 是全项目粒度的完整技术设计文档（TeamTodo 24个故事全量），而 Sprint任务拆解 是单Sprint粒度、要求"技术要点具体到API/参数"的执行文档。中间缺一道"按Sprint/模块筛选摘要"的工序。
4. **HLD-04（时序图）已核实存在**：经核对 courses-starter/演练/4 软件设计/概要设计 目录，`HLD-04-时序图设计提示词.md` 实际已存在（早期分析文档中"被引用但不存在"的判断已过期，此处予以更正），07 执行计划的阶段3不再需要新建该文件，只需在流程说明中补充其消费方与使用时机。
5. **Sprint任务拆解-Lean版的示例技术栈是硬编码的**（Prisma + Express + React + MSW + Playwright），这与 ADR 决策清单里技术层-0.5识别出的实际技术栈不一致，存在"样例偏置"风险。落地时需在材料3描述文字首行加入本项目技术栈的强指令声明，覆盖示例代码的默认倾向。

## 1.4 本轮框架优化新增内容（对应 07-流程优化执行计划）

### P0门槛规则（通用规则，不绑定具体议题）

★新增门槛：本项目由 **技术层-0.5 ADR决策清单识别** 判定为 **P0** 的全部决策，必须在进入 SAD/HLD 阶段前完成对应 ADR 的编写与评审；P1/P2 决策可与 SAD/HLD 并行推进或延后。

哪些议题会落入 P0，由每个项目自身的特征决定，不存在放之四海皆准的固定清单——判断标准是：该决策是否**架构级、难逆转，且会被 HLD-01/02/03 直接依赖其结论**。技术层-0.5 提示词已补充"决策类别参考表"作为辅助识别工具（认证与会话、权限/授权模型、数据模型与隔离、数据一致性与事务边界等），但该表只是检查项，不是强制清单，最终是否升级为 P0 仍以项目实际情况判断。

### HLD-02/03 → Sprint任务拆解 之间新增的衔接工序

- HLD-02、HLD-03 均新增 **第8章「Sprint对接摘要索引」**：一张目录级表格（编号/名称/一句话职责/关联模块/关联Story/约束标记），解决"文档粒度不匹配"问题（见 1.3 第3点）。
- 新增 **HLD-Sprint摘要提取提示词**（新文件，位于 `设计迭代衔接/提示词/4-软件设计/概要设计/`）：输入 HLD-02/03 全文 + 本 Sprint 的 Story 列表 + HLD-01 的 Story-模块映射矩阵，输出该 Sprint 范围内的技术设计摘要（含追溯ID、横切约束汇总、跨Sprint依赖提示），直接作为 **7-Sprint任务拆解-Lean版 材料3** 的标准输入，替代此前"材料3(可选)"的空缺状态。

### Sprint任务拆解🟢🟡🔴🟣初筛 与 6-AI编程流程规划V2.0精算 的分工边界

两者是**顺序衔接的两道工序**，不是互斥的替代方案：

- **7-Sprint任务拆解-Lean版**：在任务拆解阶段对每个任务做**粗筛**（🟢直接可执行 / 🟡需澄清 / 🔴高风险 / 🟣需人工设计），目的是快速给出"这批任务大致适不适合直接丢给AI"的第一轮判断，服务于 Sprint 计划会上的排期决策。
- **6-AI编程流程规划V2.0**：在任务进入实际执行前，对（尤其是🟡/🔴/🟣的）任务做**精算**——基于量化评分模型给出更细粒度的 AI 执行模式分类和 Subagent Prompt 模板，服务于具体编码时"怎么把任务喂给AI"的操作层决策。

简言之：Sprint任务拆解的标签回答"值不值得排进这个Sprint"，6-AI编程流程规划回答"具体该怎么执行"。
