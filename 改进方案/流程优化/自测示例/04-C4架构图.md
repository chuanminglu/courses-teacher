## 📐 C4模型说明

| 层次 | 英文名称 | 中文名称 | 目标受众 | 抽象级别 |
|------|---------|---------|---------|---------|
| **Level 1** | Context | 系统上下文图 | 管理层、产品 | 最高 |
| **Level 2** | Container | 容器图 | 架构师、技术负责人 | 高 |
| **Level 3** | Component | 组件图 | 开发团队 | 中 |

## 🎨 图例说明

- **蓝色框**：系统内部的容器/组件
- **灰色框**：外部系统/服务（本项目MVP阶段无第三方系统集成）
- **人形图标**：用户角色
- **实线箭头**：同步调用

## Level 1 - Context图（系统上下文图）

**目标**：展示TeamTodo在业务环境中的位置及与用户的交互关系。

```plantuml
@startuml C4_Context
!include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Context.puml

LAYOUT_WITH_LEGEND()

title 系统上下文图 - TeamTodo

Person(member, "团队成员", "创建/处理任务，参与看板协作，接收通知")
Person(pm, "项目管理员", "创建项目，管理成员与权限，查看进度报表")

System(teamtodo, "TeamTodo", "多项目任务协作管理系统\n看板任务管理、实时协作、进度报表与操作审计")

Rel(member, teamtodo, "使用", "浏览看板/处理任务/评论@提及")
Rel(pm, teamtodo, "管理", "创建项目/邀请成员/查看审计与报表")

note right of teamtodo
  【待确认】当前版本无第三方SSO/企业IM集成，
  无外部系统依赖（追溯SAD 1.4系统边界）
end note

@enduml
```

**设计要点**：
- 本系统当前无 `System_Ext` 外部系统依赖，符合SAD 1.4节"系统边界"声明的MVP范围
- 两类角色的权限差异（追溯ADR-002 RBAC）在Context层不展开，留待Container/Component层体现

## Level 2 - Container图（容器图）

**目标**：展示TeamTodo内部的主要技术容器及交互关系（追溯SAD 2.2部署视图）。

```plantuml
@startuml C4_Container
!include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Container.puml

LAYOUT_WITH_LEGEND()

title 容器图 - TeamTodo

Person(member, "团队成员/项目管理员", "通过浏览器访问")

System_Boundary(teamtodo, "TeamTodo") {
    Container(web, "Web前端", "Vue3 + Vite", "看板拖拽视图\n任务详情/评论\n实时通知展示")

    Container(api, "API服务", "Spring Boot 3 (Java 17)", "REST接口\nJWT鉴权与RBAC权限校验\n业务逻辑处理\nADR-001/002/003/004")

    Container(ws, "WebSocket网关", "Spring WebSocket (STOMP)", "看板状态实时广播\n通知实时推送\nADR-005")

    ContainerDb(mysql, "MySQL数据库", "MySQL 8.0", "用户/项目/任务/评论/通知/审计日志")

    ContainerDb(redis, "Redis", "Redis 7.x", "JWT黑名单/权限缓存\nWebSocket在线状态映射")

    Container(scheduler, "定时任务", "Spring Schedule", "报表统计/超期检测\nADR-010")
}

Rel(member, web, "访问", "HTTPS")
Rel(web, api, "调用", "REST/JSON")
Rel(web, ws, "订阅", "WSS/STOMP")

Rel(api, mysql, "读写", "MyBatis-Plus")
Rel(api, redis, "读写", "权限缓存/JWT黑名单")
Rel(api, ws, "推送事件", "任务状态变更/新通知")

Rel(ws, redis, "查询", "在线用户-实例映射")
Rel(scheduler, mysql, "读写", "定时统计/审计巡检")

@enduml
```

**设计要点**：
- API服务与WebSocket网关在物理部署上同进程（追溯SAD 2.2"WebSocket多实例共享"），此处逻辑上拆分为两个Container便于表达职责边界
- 定时任务容器对应ADR-010（P1，尚未最终决策，图中标注为规划状态）

## Level 3 - Component图（组件图：API服务内部结构）

**选择理由**：API服务是本系统业务逻辑最复杂、架构风险最高的容器（六大模块均汇聚于此），追溯SAD 2.4开发视图的代码组织结构。

```plantuml
@startuml C4_Component
!include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Component.puml

LAYOUT_WITH_LEGEND()

title 组件图 - API服务内部结构

Container(web, "Web前端", "Vue3", "前端界面")
ContainerDb(mysql, "MySQL", "MySQL 8.0", "数据存储")
ContainerDb(redis, "Redis", "Redis 7.x", "缓存/在线状态")
Container(ws, "WebSocket网关", "STOMP", "实时推送")

Container_Boundary(api, "API服务") {
    ' M1 认证与权限
    Component(auth_controller, "AuthController", "REST Controller", "登录/注册/Token刷新")
    Component(jwt_provider, "JwtTokenProvider", "Component", "签发/校验JWT\nADR-001")
    Component(perm_evaluator, "PermissionEvaluator", "Spring Security组件", "RBAC权限判定\n查ProjectMember+Redis缓存\nADR-002")

    ' M2 项目管理
    Component(project_service, "ProjectService", "Service", "项目/成员管理")
    Component(tenant_handler, "TenantLineHandler", "MyBatis-Plus插件", "自动注入projectId隔离条件\nADR-003")

    ' M3 看板视图
    Component(kanban_controller, "KanbanController", "REST Controller", "看板视图查询/筛选")

    ' M4 任务生命周期（核心聚合根）
    Component(task_service, "TaskService", "Service", "任务CRUD/指派/优先级")
    Component(task_state_machine, "TaskStateMachine", "Domain组件", "状态流转校验+乐观锁\nADR-004")

    ' M5 协作通知
    Component(comment_service, "CommentService", "Service", "评论/@提及")
    Component(notification_service, "NotificationService", "Service", "通知生成与去重")
    Component(ws_gateway, "WebSocketGateway", "Component", "按projectId广播\nADR-005")

    ' M6 报表审计
    Component(report_service, "ReportService", "Service", "进度统计")
    Component(audit_service, "AuditLogService", "Service", "审计日志写入+哈希链\nADR-006")
}

Rel(web, auth_controller, "调用", "POST /api/auth/login")
Rel(web, kanban_controller, "调用", "GET /api/kanban")

Rel(auth_controller, jwt_provider, "签发", "")
Rel(kanban_controller, perm_evaluator, "校验", "")
Rel(perm_evaluator, redis, "读取", "权限缓存")

Rel(project_service, tenant_handler, "使用", "")
Rel(kanban_controller, task_service, "查询", "")
Rel(task_service, task_state_machine, "调用", "")
Rel(task_service, mysql, "读写", "乐观锁UPDATE")

Rel(comment_service, task_service, "关联", "评论挂载Task")
Rel(comment_service, notification_service, "触发", "@提及生成通知")
Rel(notification_service, ws_gateway, "推送", "")
Rel(ws_gateway, ws, "转发", "")

Rel(task_service, audit_service, "异步触发", "Spring Event")
Rel(project_service, audit_service, "异步触发", "Spring Event")
Rel(audit_service, mysql, "写入", "audit_log(哈希链)")

Rel(report_service, mysql, "查询", "统计聚合")

@enduml
```

**设计要点**：
- 六个模块（M1~M6）在组件图中分别对应一组Component，边界与SAD 2.1逻辑视图一致
- `TenantLineHandler`（ADR-003）、`PermissionEvaluator`（ADR-002）、`TaskStateMachine`（ADR-004）、`WebSocketGateway`（ADR-005）、`AuditLogService`（ADR-006）五个组件是六篇P0级ADR决策的直接代码落点，均已在图中标注追溯编号
- `JwtTokenProvider`未在ADR-002权限组件之外重复展示，避免图元素过多（本图共14个组件，符合"8-15个"信息密度要求）

## 使用说明

- **渲染方式**：将上述PlantUML代码块粘贴至支持C4-PlantUML的渲染工具（如PlantUML本地插件、VSCode PlantUML扩展、在线PlantUML Server）
- **修改建议**：新增模块时，优先在Component图中补充对应Service组件，并标注其追溯的ADR编号（若涉及技术决策）
- **待确认项**：ADR-010（定时任务调度方案）尚未最终决策，Container图中"定时任务"容器的具体实现（Spring Schedule vs XXL-Job）需在该ADR定稿后回填
