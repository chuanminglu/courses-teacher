## 功能分组1：F001 用户认证与访问控制

### US001: 用户登录认证

**用户故事**
> 作为 所有用户，
> 我希望 通过账号密码登录系统，
> 以便 访问我的项目和任务。

**功能要点**
- 账号密码登录
- 登录成功后建立会话（JWT）
- 登录失败给出明确提示

**对应原型页面**：[登录页](../../teamtodo-prototype/login.html)（账号/密码输入、角色选择）

**验收标准（Checklist）**
- [ ] AC1 正常登录：有效账号 + 正确密码 → 登录成功，建立 JWT 会话，跳转项目/看板页，页面加载 P95 < 2s
- [ ] AC2 密码错误：账号存在但密码错误 → 提示"账号或密码错误"，不建立会话；连续失败 5 次锁定账号
- [ ] AC3 账号不存在：输入不存在的账号 → 提示"账号或密码错误"（不暴露账号是否存在），无会话建立
- [ ] 边界-空输入：账号或密码为空 → 前端提示"请输入账号/密码"
- [ ] 边界-大小写：密码区分大小写 → 大小写不符则登录失败
- [ ] 性能-登录接口：P95 < 500ms（JMeter 压测）

### US002: 用户账号管理

**用户故事**
> 作为 系统管理员，
> 我希望 能创建和停用用户账号，
> 以便 管理团队成员的访问权限。

**功能要点**
- 创建用户（姓名、账号、部门）
- 停用/启用用户
- 初始密码设置

**对应原型页面**：[用户管理页](../../teamtodo-prototype/users.html)（用户列表/创建/停用/角色）

**验收标准（Checklist）**
- [ ] AC1 创建用户：管理员填写姓名/账号/部门并提交 → 创建成功入列表，分配初始密码且加密存储，新用户可用账号+初始密码登录
- [ ] AC2 停用用户：管理员点击停用 → 状态变停用，无法登录，已有会话失效
- [ ] AC3 重复账号：提交已存在账号 → 提示"账号已存在"，不创建重复用户
- [ ] 边界-空账号：账号为空 → 提示"请输入账号"
- [ ] 边界-非管理员：普通用户访问管理页 → 无权限（提示或隐藏入口）
- [ ] 边界-停用后启用：重新启用 → 恢复可登录

### US003-Rev: 角色权限控制（权限矩阵）

**用户故事**
> 作为 所有用户，
> 我希望 系统按已拍板的权限矩阵（管理员/项目负责人/项目成员）限制我的任务操作（如非创建者不可删除他人任务），
> 以便 防止误删和越权，保障团队数据安全。

**功能要点**
- 角色模型已锁定：系统管理员、项目负责人、项目成员（澄清会方案 B）
- 权限校验贯穿创建/编辑/删除/归档/成员管理
- 按权限矩阵逐项校验，任一操作均经过权限中间件

**对应原型页面**：[登录页](../../teamtodo-prototype/login.html)（演示角色选择）、[项目成员管理页](../../teamtodo-prototype/members.html)（成员角色切换）、[用户管理页](../../teamtodo-prototype/users.html)（角色分配）

**业务规则 - 权限矩阵（测试基线）**

| 操作 | 系统管理员 | 项目负责人 | 项目成员（任务创建者） | 项目成员（非创建者） |
|------|-----------|-----------|----------------------|--------------------|
| 创建任务 | ✅ | ✅ | ✅ | ✅ |
| 编辑任务 | ✅ | ✅ | ✅（仅自己创建/指派的任务） | ⚠️ 仅被指派者可编辑 |
| 删除任务 | ✅ | ✅ | ✅（仅自己创建） | ❌ |
| 归档任务/项目 | ✅ | ✅ | ❌ | ❌ |
| 管理项目成员 | ✅ | ✅ | ❌ | ❌ |
| 查看项目任务 | ✅ | ✅ | ✅（仅已加入项目） | ✅（仅已加入项目） |

**验收标准（Checklist）**
- [ ] AC1 权限矩阵生效：四类角色执行创建/编辑/删除/归档操作 → 结果与权限矩阵逐格一致
- [ ] AC2 创建任务：管理员/项目负责人/项目成员 → 均允许创建
- [ ] AC3 编辑任务：管理员/负责人/创建者/被指派者 → 允许；非创建者且非被指派者 → 拒绝并提示
- [ ] AC4 删除任务：创建者本人/管理员 → 允许；非创建者且非管理员 → 拒绝并提示"无删除权限"，操作记入审计日志
- [ ] AC5 归档与管理成员：仅管理员/项目负责人 → 允许；项目成员 → 拒绝
- [ ] AC6 越权 API 调用：直接调用删除/归档接口 → 服务端二次校验拒绝
- [ ] AC7 越权访问数据：未加入项目用户访问该项目任务 → 拒绝（404/权限提示），不泄露数据
- [ ] 界面-权限不足：按钮置灰或操作被拦截并提示"无权限"

### US010A: 看板实时同步基础设施（WebSocket 连接管理）

**用户故事**
> 作为 团队成员，
> 我希望 系统建立 WebSocket 实时通道并自动管理连接（连接/认证/心跳/断线重连），
> 以便 为看板状态变更的实时推送提供可靠通道。

**功能要点**
- WebSocket 连接建立与 JWT 认证
- 心跳保活与断线检测
- 断线自动重连（重连间隔 ≤5s）
- 连接状态在客户端可见（已连接/重连中）
- 预留降级开关：可切换 5s 轮询模式

**对应原型页面**：[看板页](../../teamtodo-prototype/kanban.html)（实时同步连接状态指示：已连接/重连中）

**验收标准（Checklist）**
- [ ] AC1 连接建立：用户登录后进入看板 → WebSocket 连接建立并通过 JWT 认证
- [ ] AC2 认证失败：无效/过期 token → 拒绝连接
- [ ] AC3 心跳保活：连接空闲一段时间 → 心跳机制保持连接，不掉线
- [ ] AC4 断线重连：网络中断后恢复 → 自动重连（间隔 ≤5s），恢复后状态同步，无重复/遗漏
- [ ] AC5 连接状态：客户端可见"已连接/重连中"状态指示
- [ ] AC6 降级开关：切换轮询模式 → 5s 轮询拉取可用
- [ ] 边界-容量：单节点支撑 30 人内网连接稳定不掉线

- [ ] AC4 数据隔离：广播仅推送该项目在线成员，其他项目不可见

- [ ] AC2 缺省字段：仅填标题提交 → 创建成功，其余字段默认（无描述、无截止、中优先级）
- [ ] 边界-空标题：标题为空 → 前端拦截，提示"请输入标题"
- [ ] 边界-超长描述：描述超长 → 限制长度并提示

### US012: 指派任务

**用户故事**
> 作为 团队负责人，
> 我希望 能将任务指派给团队成员，
> 以便 明确任务责任人。

**功能要点**
- 选择指派人（项目成员）
- 指派后成员可见该任务

**对应原型页面**：[看板页](../../teamtodo-prototype/kanban.html)（任务表单选择指派人）

**验收标准（Checklist）**
- [ ] AC1 指派成功：选择项目成员并指派 → 任务指派人更新，被指派成员可见该任务，（若含通知）收到通知
- [ ] AC2 指派非项目成员：目标用户不在项目 → 阻止或提示"只能指派项目成员"
- [ ] 边界-重新指派：更换指派人 → 覆盖原指派人，通知新成员
- [ ] 边界-取消指派：清空指派人 → 任务回到未指派状态

- [ ] AC2 无权限编辑：非创建者/被指派者/管理员 → 系统拒绝并提示无权限

### US014: 删除任务（权限控制）

**用户故事**
> 作为 团队成员/管理员，
> 我希望 仅创建者或管理员能删除任务，
> 以便 防止误删他人任务。

**功能要点**
- 删除任务
- 权限校验（创建者/管理员）
- 删除前二次确认

**对应原型页面**：[看板页](../../teamtodo-prototype/kanban.html)（删除二次确认模态）

**验收标准（Checklist）**
- [ ] AC1 创建者删除：任务创建者点击删除并二次确认 → 任务被删除，从看板/列表移除，操作记入审计日志
- [ ] AC2 非创建者删除被拒：项目成员（非创建者、非管理员）尝试删除 → 删除按钮不可用或点击被拒，提示"无删除权限"
- [ ] AC3 二次确认：有权限用户点击删除 → 弹出确认框，确认后删除，取消则不删除
- [ ] 边界-管理员删除：管理员操作 → 允许
- [ ] 边界-删除含评论任务：任务有关联评论 → 级联处理（删除评论或保留关联，需明确）

**验收标准（Checklist）**
- [ ] AC1 详情展示：有权限用户点击任务 → 展示全部字段（标题/描述/指派人/优先级/截止日期/状态）及关联评论，页面加载 P95 < 2s
- [ ] AC2 无权限访问：直接请求无权限任务详情接口 → 服务端拒绝（403/404）

- [ ] AC2 状态值域校验：请求非法状态值 → 服务端拒绝并提示
- [ ] 边界-三态流转：待办→进行中→已完成 等合法序列可正常流转

- [ ] AC2 空评论：评论内容为空 → 前端拦截，提示"请输入评论内容"

- [ ] AC2 @非项目成员：目标用户不在项目 → 选择列表不出现该用户，或提示不可@

### US019-Rev: 通知提醒（MVP 站内信）

**用户故事**
> 作为 团队成员，
> 我希望 被指派任务时即时收到站内信、任务到期前 1 天收到提醒、被@时收到通知，
> 以便 不遗漏重要任务。

**功能要点**
- 指派任务即时站内通知（依赖 US012）
- 任务到期前 1 天提醒（定时任务每日扫描）
- 评论@提及即时站内通知（依赖 US018）
- 浏览器通知（用户授权后，可选）
- 站内信未读红点与消息列表
- 通知点击可跳转对应任务
- 预留渠道抽象接口：企业微信/邮件延后 P1

**对应原型页面**：[通知中心页](../../teamtodo-prototype/notifications.html)（站内信列表/未读/跳转）、[系统设置页](../../teamtodo-prototype/settings.html)（通知渠道开关）

**验收标准（Checklist）**
- [ ] AC1 指派通知：用户被指派新任务 → 指派动作完成后即时收到站内信通知
- [ ] AC2 到期提醒：任务截止日为明天 → 到期前 1 天触发提醒（每日 09:00 定时扫描）
- [ ] AC3 @提及通知：用户在评论中被@ → 评论发布后即时收到通知
- [ ] AC4 去重：同一任务同一事件 → 不重复触发；已完成任务不提醒
- [ ] AC5 跳转：点击通知 → 跳转对应任务
- [ ] AC6 浏览器通知：用户授权后推送浏览器通知；拒绝授权则仅站内信
- [ ] AC7 未读提示：站内信未读 → 铃铛图标显示未读数字角标
- [ ] 边界-多次提醒：同任务多日未完成 → 每天仅提醒一次
