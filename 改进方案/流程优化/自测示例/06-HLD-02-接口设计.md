## 第2章：接口设计原则与规范

### 2.1 RESTful设计原则

- 资源名词一律使用复数：`/api/v1/tasks`、`/api/v1/projects`
- 层级关系体现从属：`/api/v1/projects/{projectId}/members`、`/api/v1/tasks/{taskId}/comments`
- 动作通过HTTP方法表达，路径不出现动词（状态类动作用PATCH+子资源路径，如`/tasks/{id}/status`）

| HTTP方法 | 语义 | 幂等性 | 本项目示例 |
|---------|------|--------|------|
| GET | 查询 | ✅ | GET /api/v1/tasks/{id} |
| POST | 创建 | ❌ | POST /api/v1/tasks |
| PUT | 全量更新 | ✅ | PUT /api/v1/tasks/{id} |
| PATCH | 部分更新 | ❌（状态变更类通过乐观锁保障安全） | PATCH /api/v1/tasks/{id}/status |
| DELETE | 删除 | ✅ | DELETE /api/v1/tasks/{id} |

### 2.2 统一响应格式

**成功响应**：
```json
{ "code": 200, "message": "success", "data": {}, "timestamp": 1735084800000 }
```

**失败响应**：
```json
{ "code": 41301, "message": "任务状态版本已过期，请刷新后重试", "data": null, "timestamp": 1735084800000 }
```

### 2.3 错误码体系（按模块分段）

| 模块 | 错误码范围 | 关键示例 |
|------|-----------|------|
| MOD-001 用户认证 | 41001-41099 | 41001: 用户名或密码错误；41002: Token已失效 |
| MOD-002 项目管理 | 41101-41199 | 41101: 项目不存在；41102: 无权限操作该项目 |
| MOD-003 看板视图 | 41201-41299 | 41201: 筛选参数非法 |
| MOD-004 任务生命周期 | 41301-41399 | 41301: 任务版本冲突（乐观锁，追溯ADR-004）；41302: 非法状态流转 |
| MOD-005 协作通知 | 41401-41499 | 41401: 评论内容超长；41402: WebSocket连接鉴权失败 |
| MOD-006 报表审计 | 41501-41599 | 41501: 导出任务不存在；41502: 审计日志哈希链校验失败（追溯ADR-006） |
| 系统通用 | 50001-50099 | 50001: 系统异常 |

### 2.4 版本控制与认证

- 版本号：`/api/v1/`，v1→v2变更规则：破坏性变更（字段删除/语义变更）才升版本号
- 认证：`Authorization: Bearer {JWT}`；401=Token缺失/无效，403=Token有效但无权限（追溯ADR-002）

#### API-102: 用户登录

**基本信息**：
- **接口路径**：POST /api/v1/auth/login
- **接口功能**：校验密码，签发JWT Access Token与Refresh Token
- **所属模块**：MOD-001 用户认证与访问控制
- **认证要求**：无需认证
- **优先级**：P0
- **关联模块**：MOD-001 | **关联Story**：US001（与第8章索引一致）

**请求参数**：

| 参数名 | 类型 | 位置 | 必填 | 说明 | 校验规则 |
|--------|------|------|------|------|---------|
| username | String | Body | 是 | 用户名 | 4-20字符 |
| password | String | Body | 是 | 密码明文（HTTPS传输） | 8-20字符 |

**成功响应示例**：
```json
{
  "code": 200, "message": "success",
  "data": {
    "userId": "1001", "username": "zhangsan",
    "accessToken": "eyJhbGciOi...", "accessTokenExpiresIn": 1800,
    "refreshToken": "eyJhbGciOi...", "refreshTokenExpiresIn": 604800
  },
  "timestamp": 1735084800000
}
```

**失败响应示例**：
```json
{ "code": 41001, "message": "用户名或密码错误", "data": null, "timestamp": 1735084800000 }
```

**错误码说明**：

| 错误码 | 错误信息 | HTTP状态码 | 处理建议 |
|--------|---------|-----------|---------|
| 41001 | 用户名或密码错误 | 401 | 提示用户检查输入，不区分"用户名不存在/密码错误"以防用户名枚举攻击 |
| 41003 | 账号已被锁定（连续失败5次） | 403 | 提示用户15分钟后重试 |

**业务逻辑**：
1. 查询用户，BCrypt比对密码（追溯ADR-007）
2. 连续失败计数（Redis），达阈值锁定账号15分钟
3. 签发Access Token（30分钟）+ Refresh Token（7天），追溯ADR-001
4. 记录登录成功事件（异步，供MOD-006审计使用，追溯ADR-006）

**性能要求**：P95 < 500ms（追溯SAD 3.1性能效率指标）

**安全要求**：密码BCrypt加密比对、登录失败限流防暴力破解、Token仅通过HTTPS传输

#### API-206: 切换当前项目上下文

**基本信息**：
- **接口路径**：PUT /api/v1/context/current-project
- **接口功能**：设置用户当前操作的项目上下文，后续请求的projectId从会话上下文解析
- **所属模块**：MOD-002 多项目管理与数据隔离
- **认证要求**：需要认证
- **优先级**：P0
- **关联模块**：MOD-002 | **关联Story**：US007

**请求参数**：

| 参数名 | 类型 | 位置 | 必填 | 说明 |
|--------|------|------|------|------|
| projectId | Long | Body | 是 | 目标项目ID，必须是当前用户所属项目 |

**成功响应示例**：
```json
{ "code": 200, "message": "success", "data": { "currentProjectId": 2001 }, "timestamp": 1735084800000 }
```

**失败响应示例**：
```json
{ "code": 41102, "message": "无权限操作该项目", "data": null, "timestamp": 1735084800000 }
```

**业务逻辑**：
1. 校验`projectId`是否在`t_project_member`中存在当前用户的记录
2. 校验通过后，将`projectId`写入用户会话（前端后续请求Header携带`X-Project-Id`）
3. 后端所有涉及项目数据的查询，均由`TenantLineHandler`（追溯ADR-003）基于此`projectId`自动注入SQL隔离条件，业务代码无需手工拼接

**安全要求**：本接口是数据隔离链路的起点，`projectId`必须服务端二次校验，不可信任前端直接传入未经校验的值（追溯ADR-003"权衡分析"中的越权风险点）

#### API-405: 变更任务状态

**基本信息**：
- **接口路径**：PATCH /api/v1/tasks/{id}/status
- **接口功能**：状态机校验后变更任务状态，乐观锁防并发覆盖
- **所属模块**：MOD-004 任务生命周期管理（核心聚合根接口）
- **优先级**：P0
- **关联模块**：MOD-004 | **关联Story**：US015（同时被US009的看板拖拽复用）

**请求参数**：

| 参数名 | 类型 | 位置 | 必填 | 说明 |
|--------|------|------|------|------|
| targetStatus | String | Body | 是 | 目标状态（TODO/IN_PROGRESS/DONE等） |
| version | Integer | Body | 是 | 客户端持有的任务版本号（乐观锁，追溯ADR-004） |

**失败响应示例（409冲突）**：
```json
{
  "code": 41301,
  "message": "任务已被 李四 于 14:32 更新，请刷新后重试",
  "data": { "currentVersion": 5, "currentStatus": "IN_PROGRESS" },
  "timestamp": 1735084800000
}
```

**错误码说明**：

| 错误码 | 错误信息 | HTTP状态码 | 处理建议 |
|--------|---------|-----------|---------|
| 41301 | 任务版本冲突 | 409 | 前端拉取最新数据后提示用户重新操作（追溯SAD 3.3易用性指标） |
| 41302 | 非法状态流转（如已完成任务不可回退到待办） | 400 | 前端禁用非法状态的拖拽目标 |

**业务逻辑**：
1. `TaskStateMachine`校验`targetStatus`相对当前状态是否合法流转
2. `UPDATE t_task SET status=?, version=version+1 WHERE id=? AND version=?`，影响行数为0则判定为冲突（追溯ADR-004）
3. 更新成功后，通过`WebSocketGateway`按projectId广播状态变更事件（追溯ADR-005）
4. 异步发送审计事件（追溯ADR-006）

**性能要求**：P95 < 300ms；WebSocket广播到达延迟 < 1秒（追溯SAD 2.5场景2）

#### API-501: 发表评论

**基本信息**：
- **接口路径**：POST /api/v1/tasks/{id}/comments
- **接口功能**：发表评论，解析@提及并触发通知
- **所属模块**：MOD-005 任务内协作与通知
- **优先级**：P0
- **关联模块**：MOD-005 | **关联Story**：US017（评论）+ US018（@提及，同一接口内实现）

**请求参数**：

| 参数名 | 类型 | 位置 | 必填 | 说明 |
|--------|------|------|------|------|
| content | String | Body | 是 | 评论内容，1-2000字符，支持`@用户名`语法 |

**业务逻辑**：
1. 校验评论内容长度，写入`t_comment`（关联taskId）
2. 解析`content`中的`@用户名`片段，匹配为项目成员用户ID列表（US018）
3. 对每个被@用户，生成通知记录并去重（同一用户同一评论仅通知一次，追溯ADR-008），通过`WebSocketGateway`推送（追溯ADR-005）
4. 异步发送审计事件

**性能要求**：接口响应不因通知推送而阻塞（推送异步化）

| C-001 | 接口重复定义 | 看板拖拽（US009）与任务详情页状态变更（US015）最初各自设计了独立的状态变更接口 | API-302 vs API-405 | 统一收敛为API-405，看板侧不再单独定义接口，避免同一Task的状态变更逻辑（状态机校验+乐观锁）出现两处实现，与SAD 5.2"Task单一权威聚合根"原则一致 | ✅ 已解决 |

## 第6章：接口依赖关系

### 6.1 接口依赖关系图

```
【看板拖拽链路】
前端Vue3
  ↓ PATCH /api/v1/tasks/{id}/status (API-405)
MOD-004 TaskService（状态机+乐观锁）
  ↓ 成功后异步
MOD-005 WebSocketGateway（广播）→ 其他在线用户前端
  ↓ 同时异步
MOD-006 AuditLogService（审计写入）

【评论@提及链路】
前端Vue3
  ↓ POST /api/v1/tasks/{id}/comments (API-501)
MOD-005 CommentService
  ↓ 校验Task存在
MOD-004 TaskService.exists() (API-407内部调用，非独立网络请求)
  ↓ 解析@提及
MOD-005 NotificationService → WebSocketGateway推送
```

### 6.2 接口依赖关系表

| 调用方 | 被调用接口 | 调用场景 | 依赖类型 | 失败处理 |
|--------|-----------|---------|---------|---------|
| MOD-003看板前端 | API-405: PATCH /tasks/{id}/status | 拖拽卡片 | 同步调用 | 409冲突时提示刷新（追溯ADR-004） |
| MOD-005 CommentService | MOD-004 TaskService内部方法 | 评论前校验任务存在 | 同步内部调用（同进程，非HTTP） | 任务不存在则拒绝评论 |
| MOD-006 AuditLogService | 全部模块的写操作 | 审计留痕 | 异步（Spring Event） | 审计写入失败不影响主业务，仅记录告警日志 |
| MOD-005 WebSocketGateway | Redis在线状态映射 | 定位目标用户所在应用实例 | 同步查询 | 用户不在线则仅落库通知，不实时推送 |

## 第7章：OpenAPI 3.0规范文档（代表性接口示例）

> 说明：受篇幅限制，此处仅给出第4章6个代表性接口的OpenAPI片段作为示例，其余26个接口的YAML定义遵循同一`SuccessResponse`/`ErrorResponse`schema与`bearerAuth`安全方案生成，格式同例。

```yaml
openapi: 3.0.3
info:
  title: TeamTodo API
  description: TeamTodo多项目任务协作管理系统API文档
  version: 1.0.0
servers:
  - url: https://api.teamtodo.example.com/api/v1
    description: 生产环境

tags:
  - name: 用户认证
  - name: 项目管理
  - name: 任务管理
  - name: 协作通知
  - name: 报表审计

paths:
  /auth/login:
    post:
      tags: [用户认证]
      summary: 用户登录
      operationId: login
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [username, password]
              properties:
                username: { type: string, minLength: 4, maxLength: 20 }
                password: { type: string, minLength: 8, maxLength: 20 }
      responses:
        '200':
          description: 登录成功
          content:
            application/json:
              schema: { $ref: '#/components/schemas/SuccessResponse' }
        '401':
          description: 用户名或密码错误
          content:
            application/json:
              schema: { $ref: '#/components/schemas/ErrorResponse' }

  /tasks/{id}/status:
    patch:
      tags: [任务管理]
      summary: 变更任务状态（乐观锁）
      operationId: updateTaskStatus
      parameters:
        - name: id
          in: path
          required: true
          schema: { type: integer }
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [targetStatus, version]
              properties:
                targetStatus: { type: string, enum: [TODO, IN_PROGRESS, DONE] }
                version: { type: integer }
      responses:
        '200':
          description: 状态变更成功
        '409':
          description: 版本冲突
          content:
            application/json:
              schema: { $ref: '#/components/schemas/ErrorResponse' }

  /audit-logs:
    get:
      tags: [报表审计]
      summary: 查询审计日志
      operationId: getAuditLogs
      security:
        - bearerAuth: []
      responses:
        '200':
          description: 查询成功

components:
  schemas:
    SuccessResponse:
      type: object
      properties:
        code: { type: integer, example: 200 }
        message: { type: string, example: success }
        data: { type: object }
        timestamp: { type: integer, format: int64 }
    ErrorResponse:
      type: object
      properties:
        code: { type: integer, example: 41301 }
        message: { type: string }
        data: { type: object, nullable: true }
        timestamp: { type: integer, format: int64 }
  securitySchemes:
    bearerAuth:
      type: http
      scheme: bearer
      bearerFormat: JWT

security:
  - bearerAuth: []
```
