## 第1章：数据库设计概览

- **数据库类型**：MySQL 8.0（追溯ADR技术栈声明）+ Redis 7.x（缓存/黑名单/在线状态，非关系表不纳入本文档ER建模）
- **数据量预估**（MVP上线首年，中小团队场景）：用户≤5000、项目≤500、任务≤20万、评论≤50万、审计日志≤200万
- **表数量统计**：共15张MySQL表，覆盖6大模块中的5个（MOD-003看板视图不新增表，复用MOD-004的`t_task`表查询）

| 模块 | 表数量 |
|------|--------|

| MOD-002 多项目管理与数据隔离 | 2张 |
| MOD-004 任务生命周期管理 | 2张 |
| MOD-005 任务内协作与通知 | 3张 |
| MOD-006 进度报表与操作审计 | 3张 |
| 跨模块支撑（角色权限） | 1张（计入MOD-001） |

## 第2章：ER实体关系图

```
t_user ──1:N── t_project_member ──N:1── t_project
  │                    │
  │(1:N)               │(角色决定权限，ADR-002)
  ▼                    ▼
t_role_permission   t_task (projectId外键, ADR-003隔离)
  │                    │ 1:N
  ▼                    ▼
t_role ← N:N →      t_comment ──1:N── t_mention ──N:1── t_user
(t_role_permission)     │
                         ▼
                    t_notification ──N:1── t_user(接收者)

t_task ──1:N── t_task_history（状态变更留痕）

【全局横切】
所有写操作 ──async(Spring Event)──▶ t_audit_log（哈希链，ADR-006，独立于业务事务）
t_export_task / t_backup_record（M6独立辅助表，无强外键，避免主链路耦合）
```

**关系说明**：
- `t_user 1:N t_project_member N:1 t_project`：经典多对多通过中间表拆解，`t_project_member`同时承载"项目内角色"字段（区别于`t_role`的系统级角色）
- `t_task N:1 t_project`：任务归属唯一项目，`project_id`是数据隔离核心外键（ADR-003）
- `t_comment N:1 t_task`，`t_mention N:1 t_comment`：评论与@提及为二级从属关系
- `t_audit_log`不与任何业务表建立数据库外键约束（避免审计写入阻塞主业务事务，且哈希链要求审计表本身不可被级联删除影响）

### T-001: t_user（用户表）

**关联模块**: MOD-001 | **关联Story**: US001-US004（与第8章索引一致）

**表说明**：存储用户基本信息与登录凭证

**字段清单**：

| 字段名 | 类型 | 长度 | 主键 | 非空 | 默认值 | 说明 | 索引 |
|--------|------|------|------|------|--------|------|------|
| id | BIGINT | - | ✅ | ✅ | AUTO_INCREMENT | 用户ID | PRIMARY |
| username | VARCHAR | 20 | - | ✅ | - | 用户名 | UNIQUE |
| password_hash | VARCHAR | 100 | - | ✅ | - | BCrypt密文（追溯ADR-007，🔒不可逆加密） | - |
| email | VARCHAR | 100 | - | ✅ | - | 邮箱 | UNIQUE |
| nickname | VARCHAR | 50 | - | - | NULL | 昵称 | - |
| status | TINYINT | - | - | ✅ | 1 | 账号状态：1正常/0锁定（追溯US001登录失败锁定逻辑） | INDEX |
| failed_login_count | TINYINT | - | - | ✅ | 0 | 连续登录失败次数 | - |
| created_at | DATETIME | - | - | ✅ | CURRENT_TIMESTAMP | 创建时间 | - |
| updated_at | DATETIME | - | - | ✅ | CURRENT_TIMESTAMP ON UPDATE | 更新时间 | - |

**建表SQL**：
```sql
CREATE TABLE t_user (
  id BIGINT NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  username VARCHAR(20) NOT NULL COMMENT '用户名',
  password_hash VARCHAR(100) NOT NULL COMMENT 'BCrypt密文(ADR-007)',
  email VARCHAR(100) NOT NULL COMMENT '邮箱',
  nickname VARCHAR(50) DEFAULT NULL COMMENT '昵称',
  status TINYINT NOT NULL DEFAULT 1 COMMENT '1正常/0锁定',
  failed_login_count TINYINT NOT NULL DEFAULT 0 COMMENT '连续登录失败次数',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_username (username),
  UNIQUE KEY uk_email (email),
  KEY idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

**分表策略**：数据量预估≤5000，MVP阶段不分表；若未来支持SaaS多租户对外开放，需评估按注册来源分表

**数据量预估**：首年≤5000行，年增长率约30%

### T-007: t_project_member（项目成员表）

**关联模块**: MOD-002 | **关联Story**: US006、US007

**表说明**：项目与用户的多对多关联，同时承载项目内角色（隔离与权限判定的核心表，追溯ADR-002/ADR-003）

**字段清单**：

| 字段名 | 类型 | 长度 | 主键 | 非空 | 默认值 | 说明 | 索引 |
|--------|------|------|------|------|--------|------|------|
| id | BIGINT | - | ✅ | ✅ | AUTO_INCREMENT | - | PRIMARY |
| project_id | BIGINT | - | - | ✅ | - | 项目ID（追溯ADR-003隔离字段） | INDEX（复合） |
| user_id | BIGINT | - | - | ✅ | - | 用户ID | INDEX（复合） |
| project_role | VARCHAR | 20 | - | ✅ | 'MEMBER' | 项目内角色：ADMIN/MEMBER（追溯ADR-002） | - |
| joined_at | DATETIME | - | - | ✅ | CURRENT_TIMESTAMP | 加入时间 | - |

**建表SQL**：
```sql
CREATE TABLE t_project_member (
  id BIGINT NOT NULL AUTO_INCREMENT,
  project_id BIGINT NOT NULL COMMENT '项目ID(ADR-003隔离字段)',
  user_id BIGINT NOT NULL,
  project_role VARCHAR(20) NOT NULL DEFAULT 'MEMBER' COMMENT 'ADMIN/MEMBER(ADR-002)',
  joined_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_project_user (project_id, user_id),
  KEY idx_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='项目成员表';
```

**设计要点**：`uk_project_user`唯一约束防止重复邀请；`PermissionEvaluator`（追溯ADR-002）以`(project_id, user_id)`为键查询本表并缓存至Redis（TTL 5分钟）

**分表策略**：数据量与`t_project × 平均成员数`线性相关，预估≤5万行，不分表

### T-008: t_task（任务表，核心聚合根）

**关联模块**: MOD-004 | **关联Story**: US011-US016（同时被US008/US009查询与状态变更复用）

**表说明**：任务生命周期主表，`version`字段实现乐观锁（追溯ADR-004），`status`字段驱动状态机（追溯B4-07第2章状态机视图）

**字段清单**：

| 字段名 | 类型 | 长度 | 主键 | 非空 | 默认值 | 说明 | 索引 |
|--------|------|------|------|------|--------|------|------|
| id | BIGINT | - | ✅ | ✅ | AUTO_INCREMENT | 任务ID | PRIMARY |
| project_id | BIGINT | - | - | ✅ | - | 所属项目（追溯ADR-003隔离） | INDEX（复合） |
| title | VARCHAR | 200 | - | ✅ | - | 标题 | - |
| description | TEXT | - | - | - | NULL | 描述 | - |
| status | VARCHAR | 20 | - | ✅ | 'TODO' | 状态：TODO/IN_PROGRESS/DONE/ARCHIVED（不可为空约束追溯B4-07状态机） | INDEX（复合） |
| priority | TINYINT | - | - | ✅ | 2 | 优先级：1高/2中/3低 | INDEX |
| assignee_id | BIGINT | - | - | - | NULL | 负责人用户ID | INDEX |
| version | INT | - | - | ✅ | 0 | 乐观锁版本号（追溯ADR-004，🔁每次UPDATE自增） | - |
| deleted | TINYINT | - | - | ✅ | 0 | 软删除标记（追溯US016归档） | - |
| created_at | DATETIME | - | - | ✅ | CURRENT_TIMESTAMP | - | - |
| updated_at | DATETIME | - | - | ✅ | CURRENT_TIMESTAMP ON UPDATE | - | - |

**建表SQL**：
```sql
CREATE TABLE t_task (
  id BIGINT NOT NULL AUTO_INCREMENT,
  project_id BIGINT NOT NULL COMMENT '所属项目(ADR-003)',
  title VARCHAR(200) NOT NULL,
  description TEXT DEFAULT NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'TODO' COMMENT 'TODO/IN_PROGRESS/DONE/ARCHIVED',
  priority TINYINT NOT NULL DEFAULT 2 COMMENT '1高/2中/3低',
  assignee_id BIGINT DEFAULT NULL,
  version INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本号(ADR-004)',
  deleted TINYINT NOT NULL DEFAULT 0 COMMENT '软删除标记',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_project_status (project_id, status),
  KEY idx_assignee (assignee_id),
  KEY idx_priority (priority),
  FULLTEXT KEY ft_title_desc (title, description)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='任务表(核心聚合根)';
```

**并发控制**（追溯ADR-004，B4-07第6章并发冲突）：
```sql
UPDATE t_task SET status = #{targetStatus}, version = version + 1, updated_at = NOW()
WHERE id = #{id} AND version = #{version} AND deleted = 0;
-- 影响行数为0 → 抛出乐观锁冲突异常，返回错误码41301（追溯06-HLD-02接口设计 API-405）
```

**分表策略**：预估首年≤20万行，MVP阶段不分表；超过500万行时按`project_id`哈希分表（追溯质量要求"单表>500万需分表"），需评估MyBatis-Plus分片插件接入成本

### T-012: t_notification（通知表）

**关联模块**: MOD-005 | **关联Story**: US019-Rev

**表说明**：存储@提及/指派等触发的通知记录，去重逻辑追溯ADR-008

**字段清单**：

| 字段名 | 类型 | 长度 | 主键 | 非空 | 默认值 | 说明 | 索引 |
|--------|------|------|------|------|--------|------|------|
| id | BIGINT | - | ✅ | ✅ | AUTO_INCREMENT | - | PRIMARY |
| receiver_id | BIGINT | - | - | ✅ | - | 接收用户ID | INDEX（复合） |
| source_type | VARCHAR | 20 | - | ✅ | - | 来源类型：COMMENT_MENTION/TASK_ASSIGN | - |
| source_id | BIGINT | - | - | ✅ | - | 来源记录ID（如comment_id） | - |
| dedup_key | VARCHAR | 64 | - | ✅ | - | 去重键：source_type+source_id+receiver_id哈希（追溯ADR-008，🔁防重复通知） | UNIQUE |
| is_read | TINYINT | - | - | ✅ | 0 | 已读标记 | INDEX（复合） |
| created_at | DATETIME | - | - | ✅ | CURRENT_TIMESTAMP | - | - |

**建表SQL**：
```sql
CREATE TABLE t_notification (
  id BIGINT NOT NULL AUTO_INCREMENT,
  receiver_id BIGINT NOT NULL,
  source_type VARCHAR(20) NOT NULL COMMENT 'COMMENT_MENTION/TASK_ASSIGN',
  source_id BIGINT NOT NULL,
  dedup_key VARCHAR(64) NOT NULL COMMENT '去重键(ADR-008)',
  is_read TINYINT NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_dedup (dedup_key),
  KEY idx_receiver_read (receiver_id, is_read)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='通知表';
```

**设计要点**：`uk_dedup`唯一索引是ADR-008去重机制的数据库层兜底（应用层已判重，数据库唯一约束防止并发场景下的重复插入）

### T-013: t_audit_log（审计日志表）

**关联模块**: MOD-006 | **关联Story**: US021

**表说明**：全局操作审计，哈希链防篡改（追溯ADR-006）

**字段清单**：

| 字段名 | 类型 | 长度 | 主键 | 非空 | 默认值 | 说明 | 索引 |
|--------|------|------|------|------|--------|------|------|
| id | BIGINT | - | ✅ | ✅ | AUTO_INCREMENT | - | PRIMARY |
| operator_id | BIGINT | - | - | ✅ | - | 操作人 | INDEX（复合） |
| resource_type | VARCHAR | 20 | - | ✅ | - | 资源类型：TASK/PROJECT/USER | INDEX（复合） |
| resource_id | BIGINT | - | - | ✅ | - | 资源ID | - |
| action | VARCHAR | 20 | - | ✅ | - | 操作类型：CREATE/UPDATE/DELETE | - |
| detail | JSON | - | - | - | NULL | 变更详情快照 | - |
| prev_hash | CHAR | 64 | - | ✅ | - | 上一条记录哈希（追溯ADR-006哈希链，🔒不可篡改） | - |
| hash | CHAR | 64 | - | ✅ | - | 本条记录哈希 = SHA256(prev_hash+本行内容) | - |
| created_at | DATETIME | - | - | ✅ | CURRENT_TIMESTAMP | - | INDEX |

**建表SQL**：
```sql
CREATE TABLE t_audit_log (
  id BIGINT NOT NULL AUTO_INCREMENT,
  operator_id BIGINT NOT NULL,
  resource_type VARCHAR(20) NOT NULL COMMENT 'TASK/PROJECT/USER',
  resource_id BIGINT NOT NULL,
  action VARCHAR(20) NOT NULL COMMENT 'CREATE/UPDATE/DELETE',
  detail JSON DEFAULT NULL,
  prev_hash CHAR(64) NOT NULL,
  hash CHAR(64) NOT NULL COMMENT '哈希链(ADR-006)',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_operator_time (operator_id, created_at),
  KEY idx_resource (resource_type, resource_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='审计日志表';
```

**安全要求**（追溯ADR-006）：数据库账号层面对本表仅授予`INSERT`、`SELECT`权限，不授予`UPDATE`、`DELETE`权限，从数据库权限层杜绝篡改可能

**分表策略**：预估首年≤200万行，按季度归档（超过1年的历史记录归档至冷存储，主表仅保留近1年在线查询）

## 第5章：索引优化策略

| 表名 | 查询场景 | 索引名 | 索引字段 | 索引类型 | 预估性能提升 |
|------|---------|--------|---------|---------|-------------|
| t_task | 看板按项目+状态分列查询（US008） | idx_project_status | (project_id, status) | 复合索引 | 全表扫描→索引扫描，大数据量下提升90%+ |
| t_task | 按负责人筛选（US010B） | idx_assignee | assignee_id | 普通索引 | - |
| t_task | 标题/描述关键词搜索（US010A） | ft_title_desc | (title, description) | 全文索引 | 替代LIKE '%kw%'的全表扫描（追溯ADR-009 MVP方案） |
| t_project_member | 权限校验高频查询（US003/US006） | uk_project_user | (project_id, user_id) | 唯一复合索引 | 天然覆盖PermissionEvaluator查询模式 |
| t_notification | 未读通知列表查询（US019-Rev） | idx_receiver_read | (receiver_id, is_read) | 复合索引 | - |
| t_notification | 去重校验 | uk_dedup | dedup_key | 唯一索引 | 数据库层兜底应用层判重（ADR-008） |
| t_audit_log | 按操作人+时间范围查询（US021） | idx_operator_time | (operator_id, created_at) | 复合索引 | - |
| t_comment | 按任务查询评论列表（US017） | idx_task_id | task_id | 普通索引 | - |
